Projeto: Evolução TCP/IP para QUIC
Trabalho prático - Mostra como funciona de verdade

Objetivo do Trabalho

Mostrar na prática a evolução dos protocolos de transporte, desde TCP/IP até QUIC, com demonstração real do funcionamento.

Aluno: Agostinho Mandava | Tema 1

1. Como funciona o TCP (antigo)

1
Cliente envia SYN
2
Servidor responde SYN-ACK
3
Cliente envia ACK + TLS (2 viagens extras)
4
Só agora começa a mandar dados

Total: 3 viagens (RTT) - Lento em rede móvel

2. Como funciona o QUIC (novo)

1
Cliente envia tudo junto (já com TLS) - 1 viagem
2
Na segunda vez: 0 viagens! Já manda dados direto

Vantagens que você pode explicar:

  • Streams independentes: se um pacote perde, outros continuam
  • Muda de Wi-Fi para 4G sem cair (usa ID, não IP)
  • Tudo criptografado sempre

3. Demonstração Real - Você mostra na turma

Não precisa instalar nada. Mostra assim no projetor:

  1. Abra o Chrome e vá no YouTube
  2. Aperte F12 > Aba Rede (Network)
  3. Recarregue a página
  4. Na coluna Protocolo vai aparecer h3 = QUIC funcionando de verdade
Prova real:
youtube.com  → h3 (QUIC)
google.com   → h3 (QUIC)
facebook.com → h3 (QUIC)

Isso prova que o que explicamos já está no ar!

Como o site ativa QUIC (código real):

# Servidor Apache/Nginx ativa HTTP/3 com 1 linha:
# nginx: listen 443 quic reuseport;

# Chrome ativa sozinho, mas pode forçar:
chrome://flags/#enable-quic → Enabled

Conclusão para falar

TCP foi bom para internet fixa, mas QUIC foi feito para internet móvel. É 3x mais rápido, não trava e não cai ao trocar de rede. Por isso YouTube e Google já usam. É a evolução natural dos protocolos de transporte.
